# SecurityQuote — 隐形价差（Implicit / Effective Spread）

本文件为 `level1::SecurityQuote`（C++）和 `level1::SecurityQuote`（Rust）提供隐形价差（隐含价差 / effective spread）的说明、算法、市场意义与使用示例。

## 概要

隐形价差（implicit / effective spread）用于衡量交易执行价格相对于买卖档位中点（mid-price）的偏离程度，是市场微观结构中常用的衡量交易成本与做市/流动性的指标。

在本项目中，已在以下代码位置实现：

- C++: `quant1x/level1/security_quote.h` （方法名：`implicitSpread()` 与 `implicitSpreadPct()`）
- Rust: `quant1x/level1/security_quote.rs` （方法名：`implicit_spread()` 与 `implicit_spread_pct()`）

## 算法说明

1. 基本定义（首选）

   effective spread = 2 * |trade_price - midpoint(bid1, ask1)|

   - midpoint(bid1, ask1) = (bid1 + ask1) / 2
   - trade_price 使用行情快照中的 `price` 字段

   解释：如果交易价格恰好处在买卖中点，则 effective spread = 0（表明无显性价差）；若交易价格偏离 mid，则乘 2 得到双边价差估计（模拟从 mid 到对侧价位的总价差）。

2. 回退策略（当数据不完整或缺失时）

   - 若 `price` 不可用（<= 0 或 NaN），但有有效的 `bid1` 与 `ask1`，则使用在盘价差作为回退：

     implicit spread = ask1 - bid1

   - 若 `bid1` / `ask1` 亦不可用，则返回 0.0（无可计算信息）。

3. 百分比形式

   implicit spread (%) = implicit_spread / midpoint * 100

   - 若 midpoint 不可用，则回退使用 `lastClose` 作为基准（即 implicit_spread / lastClose * 100）
   - 若无可用基准，返回 0.

## 市场意义

- 隐形价差是衡量执行成本与市场流动性的常用指标：
  - 较小的隐形价差通常表示高流动性、低交易成本；
  - 较大的隐形价差可能表示薄弱流动性、较高交易成本、或存在信息不对称/冲击性交易。

- 在做市和量化策略中，隐形价差可用于：
  - 监控市场微结构健康（跨时序或跨品种对比）；
  - 作为交易成本估计输入（例如回测时将手续费/价差替换为隐形价差）；
  - 风控或交易信号过滤（当隐形价差过大时降低仓位或暂停交易）。

## 使用示例

C++（在 `SecurityQuote` 实例 `q` 上调用）

```cpp
// 价差（价格单位）
auto spread = q.implicitSpread();

// 价差百分比（%）
auto spread_pct = q.implicitSpreadPct();

// 例子
if (spread_pct > 0.5) {
    spdlog::warn("{}{} 隐形价差过大: {}%", exchange::GetMarketFlag((exchange::ExchangeId)q.market), q.code, spread_pct);
}
```

Rust（在 `SecurityQuote` 实例 `q` 上调用）

```rust
let spread = q.implicit_spread();
let spread_pct = q.implicit_spread_pct();

if spread_pct > 0.5 {
    log::warn!("{}{} 隐形价差过大: {:.3} %", q.market, q.code, spread_pct);
}
```

## 注意事项和边界情况

- 浮点数精度：在比较隐形价差或写单元测试时，请使用近似比较（例如 `EXPECT_NEAR` 或 `assert!((a-b).abs() < eps)`）来避免平台/实现带来的微小舍入差异。

- 全局初始化副作用：库初始化（例如 `lazy_init`）可能会在测试或程序启动时读取用户目录 `~/.q1x/quant1x.yaml` 等配置；若希望测试独立且无副作用，请在测试中设置 `QUANT1X_HOME` 到临时目录或修改测试初始化逻辑。

- 定义选择：`2 * |price - mid|` 是常见估计，但并不是唯一的隐形价差定义；某些研究或需求可能使用 signed effective spread（保留符号以表示买卖偏向）或基于成交量加权的变体。

## 隐形价差常见区间与市场预判（经验性指导）

下面是一些经验性阈值和对应的可能市场含义。注意：这些阈值是经验建议，实际阈值应根据品种（如 A 股大盘股、创业板、小盘股、期货、外汇等）、时间段（盘中/盘后/开盘收盘集合竞价）与交易单位进行标定。

- 极低隐形价差（spread_pct < 0.05%）
  - 含义：高流动性、窄价差，做市活跃，交易成本低。
  - 场景：大盘蓝筹股、活跃期货合约、外汇主要货币对。
  - 交易建议：可适当放宽做市/主动开仓的限制，短期套利/高频策略适合。

- 低隐形价差（0.05% ≤ spread_pct < 0.2%）
  - 含义：流动性良好，市场处于正常状态。
  - 场景：中等流动性的股票或小止损的日内交易。
  - 交易建议：常规策略与日内策略可正常运行，注意在高波动时刻回避。

- 中等隐形价差（0.2% ≤ spread_pct < 0.8%）
  - 含义：流动性下降，订单簿可能较薄或存在大单压力。
  - 场景：小盘股、次新股或在不活跃时段。
  - 交易建议：降低杠杆/仓位，增加止损宽度；若为做市策略，逐步收紧报价或减少挂单数量。

- 高隐形价差（0.8% ≤ spread_pct < 2%）
  - 含义：显著流动性问题，可能有重大信息、盘中冲击或市场拥堵。
  - 场景：公司重大消息发布时、盘中剧烈波动或薄市时段。
  - 交易建议：暂停主动做市和高频交易；避免以市价重仓进出；考虑转为被动挂单并缩小交易规模。

- 极高隐形价差（spread_pct ≥ 2%）
  - 含义：市场极不健康或严重流动性缺失，可能接近停牌/退市或出现极端行情。
  - 场景：退市个股、停牌前后、极端事件（系统性风险、交易中断）。
  - 交易建议：除非有特殊套利逻辑，否则避免交易；风控层面触发硬性保护（平仓/禁止下单）。

### 对阈值的进一步说明与校准

- 标定方法：对历史样本进行分位数分析（按日/按分钟）来确定基线中位数与 95% 分位数，然后选择适合的报警阈值（例如：将中位数作为正常基线、95% 分位数作为高价差报警）。
- 市场与品种差异：同一阈值对不同品种意义不同，建议为每个交易品种或品种族群维护单独的基线与阈值。
- 时间敏感性：在开盘集合竞价或收盘集合竞价期间，价差行为不同（非连续成交），应排除或使用专门的阈值处理。

### 实时策略建议（示例）

- 监控流：每分钟计算一段时间窗口（例如 1 分钟或 5 分钟）的 spread_pct 中位数与标准差，若当前 spread_pct 超过基线 + k * std（例如 k=3）触发警报。
- 交易过滤：在撮合前检查实时 spread_pct，若高于阈值则拒单或降级为被动限价单；低于阈值则允许主动市价撮合（可结合成交量与委托簿深度判断）。
- 统计回测：在回测框架中把隐形价差作为交易成本模型的一部分，以更真实地估计策略净收益。

### 风控与审计

- 记录：对每笔交易记录当时的 spread 与 spread_pct，便于事后审计、滑点分析与成本分解。
- 警报：将高隐形价差事件纳入风控仪表盘，结合成交量/委托簿深度/新闻事件触发人工或自动化响应。

以上建议为经验性指导，实际使用时请结合历史数据与品种特征调整阈值与策略。

## 阀值常量与枚举含义（详细说明）

在代码中我们使用枚举 `SpreadLevel` 与一组默认常量来对隐形价差进行分级。下面逐项说明这些常量的数值含义、适用场景与建议操作。

注意：`implicitSpreadPct()` 返回的是百分比数值（即已经乘以 100 的结果）。例如返回 `0.05` 表示 `0.05%`，不是小数形式 `0.0005`。

1) SpreadLevel 枚举

 - VERY_LOW（极低）
   - 数值区间：pct < `SPREAD_PCT_VERY_LOW`（默认 `0.05`，即 < 0.05%）
   - 含义：市场非常活跃、买卖价格接近中点，成交价与 mid 基本重合，表明流动性极好。
   - 建议：可允许主动成交、做市策略放宽限制，适合高频/短期套利。

 - LOW（低）
   - 数值区间：`SPREAD_PCT_VERY_LOW` ≤ pct < `SPREAD_PCT_LOW`（默认 `0.05% - 0.2%`）
   - 含义：流动性良好，买卖价差较窄，市场运行正常。
   - 建议：常规交易与日内策略可继续执行；若结合成交量/深度指标可进一步放宽或收紧策略。

 - MEDIUM（中等）
   - 数值区间：`SPREAD_PCT_LOW` ≤ pct < `SPREAD_PCT_MEDIUM`（默认 `0.2% - 0.8%`）
   - 含义：流动性有所下降，订单簿较薄或存在较大单的影响；滑点风险上升。
   - 建议：降低仓位或减少被动/主动下单频率；对冲/做市策略应缩减挂单数量与报价大小。

 - HIGH（高）
   - 数值区间：`SPREAD_PCT_MEDIUM` ≤ pct < `SPREAD_PCT_HIGH`（默认 `0.8% - 2.0%`）
   - 含义：显著的流动性问题，可能有突发性消息、市场拥堵或极端波动。
   - 建议：暂停主动做市与高频交易；改用小规模被动限价单或等待市场稳定；风控触发更严格的开/平仓限制。

 - VERY_HIGH（极高）
   - 数值区间：pct ≥ `SPREAD_PCT_HIGH`（默认 ≥ 2.0%）
   - 含义：市场极端薄弱、接近停牌或出现极端事件（公司事件、系统性风险、假盘等）。
   - 建议：默认禁止交易或只允许手工/审批流程下单；风控应进行强制平仓或锁仓处理，排查是否为数据异常。

2) 常量数值说明（默认值）

 - `SPREAD_PCT_VERY_LOW = 0.05`  -> 表示 0.05%（非常窄的隐形价差）
 - `SPREAD_PCT_LOW = 0.2`        -> 表示 0.2%
 - `SPREAD_PCT_MEDIUM = 0.8`     -> 表示 0.8%
 - `SPREAD_PCT_HIGH = 2.0`       -> 表示 2.0%

3) 关于阈值的使用建议

 - 默认值是经验值，仅做示例与快速启用用途。生产环境请基于历史样本对每个品种或品种簇单独标定阈值。
 - 建议使用分位数法（例如按分钟/日计算中位数与 95% 分位）来生成基线与告警阈值。
 - 对于高频或短线策略，可设置更严格（更低）的阈值；而长期或低频策略可容忍较高阈值。

4) 在代码中的可替代实现

 - 若需要可运行时调整：可把这些常量放入配置文件（如 `quant1x.yaml`），运行时加载并替换默认值；并在 `SecurityQuote` 的相关函数中读取配置值而非硬编码常量。
 - 也可以为每个 market/code 保存各自的动态基线（滚动窗口的中位数/标准差），并以相对偏离来判断等级（比使用全局常量更鲁棒）。

5) 日志与监控建议

 - 在关键风控/下单路径记录 `spread_pct` 与 `SpreadLevel`，便于事后分析与指标回测。
 - 在风控面板中把各等级作为不同颜色/优先级的告警展示，方便运营人员快速判断市场状态。
